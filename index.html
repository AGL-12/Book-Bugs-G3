Origen y Contextualización

Nacimiento e impacto del proyecto en el sector editorial

¿Por qué Book & Bugs?

El proyecto Book & Bugs nace como una respuesta tecnológica a la brecha digital que sufren las pequeñas y medianas librerías. Tras un análisis del sector, se evidencia que la dependencia de sistemas obsoletos o manuales para el control de inventario provoca descuadres de stock, ineficiencia administrativa y una menor retención de clientes frente a las grandes plataformas de comercio electrónico.

Para resolver esta problemática, se ha desarrollado una solución integral de escritorio utilizando JavaFX para una experiencia de usuario fluida, respaldada por una arquitectura de base de datos relacional gestionada mediante Hibernate 5.2 (JPA). La aplicación no solo centraliza la gestión del catálogo y los usuarios en tiempo real, sino que aporta un valor diferencial al incluir módulos interactivos para el cliente: carrito de compras dinámico, historial de pedidos y un sistema de valoraciones (reseñas y estrellas) que fomenta el engagement y la fidelización.

Objetivos Específicos

Funcionalidades principales de la aplicación

💻

Descripción general

La aplicación tiene tres tipos de usuario: visitante, cliente y administrador. Todos pueden ver el catálogo de libros. El cliente puede comprar y comentar. El administrador gestiona el sistema sin comprar ni comentar.

👁️

Visitante

Puede navegar por el catálogo de libros sin necesidad de iniciar sesión.

👤

Cliente

Al iniciar sesión, puede comprar libros, consultar su historial de pedidos y dejar valoraciones con estrellas. Cada cliente tiene un carrito de compras por sesión.

⚙️

Administrador

No compra ni comenta. Su función es gestionar los libros y los usuarios del sistema, con validaciones y control de errores.

Seguimiento

Metodología de control y organización del proyecto

📅

Organización y herramientas

A la hora de llevar a cabo un proyecto en equipo, es indispensable contar con una buena organización que permita avanzar de forma eficiente. Para ello, utilizamos GitHub como sistema de control de versiones, empleando una estrategia de ramas para separar el desarrollo de backend, frontend y documentación.

La comunicación diaria se mantuvo mediante un grupo de WhatsApp, mientras que las reuniones semanales servían para revisar el avance respecto al cronograma definido en GanttProject y replanificar en caso de ser necesario.

🧪

Evaluación y pruebas

La evaluación del software consiste en verificar que el producto cumple con los requisitos establecidos. Para ello, se diseñaron pruebas unitarias con JUnit para la lógica de negocio y pruebas de interfaz con TestFX para validar el funcionamiento de las pantallas principales.

Se probó la aplicación con usuarios de prueba para validar el comportamiento en un uso real. Las incidencias detectadas fueron corregidas antes de la entrega final del proyecto.
